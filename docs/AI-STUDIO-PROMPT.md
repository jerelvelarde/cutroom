# Cutroom AI Studio prototype brief

Build a polished, working React + TypeScript prototype named Cutroom: a proactive personal-photo/video editor that finds the story in a camera roll and turns it into a vertical reel. Use CopilotKit for the assistant. Make its interaction and visual design feel familiar to Google Photos, with original Cutroom branding.

PRODUCT / SCOPE
Primary story: Today. Import up to 50 photos/videos, choose a day, automatically select roughly 6–12 good moments, and produce a 30-second 9:16 story (15-second option for a demo). Stretch: My SF tech week, up to 100 assets over a chosen date range, 45 seconds. No written brief or manual shot selection required; optional direction and revisions are welcome. Capture dates must be explicit: use metadata when available, show Unknown date otherwise, allow batch date assignment; never silently equate import time with capture time. Use America/Los_Angeles for the event demo, October 25, 2026.

VISUAL DIRECTION: GOOGLE PHOTOS PATTERNS
Light, airy, photo-first interface. Warm white canvas, soft gray navigation rail, charcoal text, restrained blue primary actions and pale blue selected states, rounded search field and pills, generous breathing room. Use a clean readable sans-serif. Compact left navigation (Photos, Stories), top search, Import button, date-grouped responsive media grid with mixed photo/video thumbnails, duration badges, hover selection circles and an accessible selected-items toolbar. Keep images central rather than building a metrics dashboard. Brand it Cutroom using a simple original icon, not Google's logo. Small horizontal story cards for Today and SF tech week above the library, plus an inviting clear empty state. On story creation, transition to an artifact workspace with a large 9:16 video/story preview, shot strip, and a collapsible assistant on the right. Show source-shot reasons on demand. Avoid purple gradients, giant marketing hero sections, unnecessary stat cards, debug panels, and raw API identifiers in the product UI. Mobile should have a useful grid and dismissible assistant sheet.

COPILOTKIT IS A REAL DEPENDENCY
Use official CopilotKit React components for chat/input/streaming/stop, not a hand-made lookalike. Consult current official docs and installed types before choosing exact APIs. Current guidance uses @copilotkit/react and @copilotkit/core, CopilotKitProvider, CopilotChat/CopilotSidebar and @copilotkit/react/styles.css; backend @copilotkit/runtime and an AG-UI agent adapter can bridge our Gemini workflow. Keep one conversation per story. Do not use old react-core/react-ui examples blindly. Self-host the runtime within the app if supported; do not require a CopilotCloud subscription or separate account. Use domain-specific assistant cards: selected shot thumbnails and reasons, proposed timeline changes, review findings, and render receipts. The assistant must be able to perform reversible changes through typed tools (change story duration, remove/replace a selected shot, revise title, set story window) with undo, rather than merely describe them.

GOOGLE HACKATHON TECH
Use gemini-4-argon through Google's Interactions API for actual visual analysis, narrative selection and critique where supported. The intended managed editor is antigravity-preview-09-2026 with agent_config {type:'antigravity', model:'gemini-4-argon'}, environment:'remote'. It coordinates constrained edit/render/review tools; direct Argon handles video understanding. The production architecture uses local FFmpeg and Remotion; this AI Studio prototype must honestly expose any rendering/runtime limitations. Do not silently substitute OpenAI or another Gemini model. Use the platform's server-side Gemini secret configuration; never embed API keys in browser code, examples, logs, or the chat prompt. Our hackathon key already works, but no secret is supplied in this prompt.

WORKING PROTOTYPE REQUIREMENTS
1. Working multiple-file input and drag/drop for image/video files; real local object-URL thumbnails and playback; remove items, select items, filter by date, assign missing dates, enforce count limits, and revoke URLs on removal. Start with a clearly labeled Sample library of representative licensed/public sample imagery or generated placeholders, with fictional captions/dates clearly identified as sample data; never imply these are the user's real memories. Make switching to imported files easy.
2. Today and SF tech week controls with dates and output duration. Automatically create a structured editable timeline from actual analysis when connected. Expose actual upload/analysis status and useful error/retry UI. Upload only relevant selected previews for private Google analysis, with an understandable initial notice; no public media upload or auto-posting.
3. Real assistant controls that update shared gallery/story state, with compact useful tool-result cards.
4. Playable story preview with ordered shots, readable opening/ending titles, restrained image motion and transitions. Use Remotion Player if supported. Download MP4 only when real encoding succeeds. If browser/AI Studio can't encode, provide a working preview and downloadable timeline JSON and label MP4 export unavailable; never download fake MP4 bytes or claim a rendered file exists.
5. Show actual phases Understand → Select → Edit → Review. For live APIs, expose real tool events and measured checks, not fabricated percentages or canned success. A clearly labeled Sample walkthrough can illustrate the experience while disconnected, but it must never be presented as a genuine Argon run or real repair.
6. Final review checks must distinguish deterministic dimensions/duration/source-bounds checks from Gemini visual critique. Only report a repair if it really changes the artifact and is rechecked. User reviews and downloads; no automatic publishing.
7. Functional empty/loading/error/completed states, accessible buttons/keyboard selection, responsive desktop/mobile. Keep personal files, previews and credentials out of GitHub and public app assets. Do not deploy publicly.

Build the app now, run it and fix compile/runtime issues. Prioritize a beautiful working Google-Photos-inspired gallery plus actual CopilotKit-driven story editing and preview. Keep adapters modular so this prototype can be merged into our local React/Node Cutroom backend later. Report exactly what is live versus sample-only and any unsupported managed-agent/render integration. Do not claim end-to-end functionality that was not exercised. Technical setup details belong in developer documentation, not the main user flow.
